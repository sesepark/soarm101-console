# 원격 추론 배관 검증 — 2026-09-07

대상은 `2898f3a`와 Spark의 다음 체크포인트다.

```text
/home/sehwan_spark/outputs/soarm101_cube104_dn_strat__pi05__b67e/checkpoints/002000/pretrained_model
```

## 결론

**부분 실패다.** Spark 학습 동결/재개, SSH 터널, 서버 기동, 체크포인트 적재와 정책 자체의
추론은 모두 동작했다. 그러나 `2898f3a`의 실제 콘솔 입력인 `scene`/`wrist`를 보내면 LeRobot
0.6.1 서버가 체크포인트의 rename processor를 적용하기 전에 `scene`을 정책 feature에서 찾아
첫 관측이 실패한다.

따라서 아래 `365.16 ms`는 **정책 키를 직접 넣은 진단 전용 측정값**이다. 현재 콘솔 배관의
end-to-end 성공값으로 보면 안 된다. 실제 콘솔 경로의 지연은 측정하지 못했다.

## 팔을 움직이지 않은 방법

`RobotClient`는 만들지도 import하지도 않았다. 이 클래스는 생성 과정에서 follower에 연결하고
제어 루프가 받은 액션을 팔로 보내므로 이번 검증에는 사용할 수 없다. 대신
`scripts/verify_remote_policy_pipeline.py`가 SSH 터널 너머 gRPC에 검은 합성 영상 두 장과 0인
관절 상태를 보냈다. 반환된 action chunk는 메모리에서 길이만 확인하고 모두 버렸다. follower
serial과 실제 카메라는 한 번도 열리지 않았다.

## 4. 추론 지연

먼저 실제 콘솔과 같은 `scene`/`wrist` 입력으로 실행한 결과다.

```text
INFO 2026-09-07 19:51:56 y_server.py:169 Time taken to put policy on cuda: 140.7136 seconds
INFO 2026-09-07 19:51:56 y_server.py:224 Running inference for observation #0 (must_go: True)
ERROR 2026-09-07 19:51:56 y_server.py:264 Error in StreamActions: 'observation.images.scene'
```

즉, **현재 콘솔 배관은 첫 관측에서 실패하며 end-to-end 지연값은 없다.**

팔 없이 정책 자체의 성능은 잴 수 있으므로, 두 번째 시행에서는 진단 목적으로 영상 feature를
체크포인트가 기대하는 `base_0_rgb`/`left_wrist_0_rgb`로 직접 구성하고 rename override를 비웠다.
이는 콘솔 구현을 통과한 값이 아니다.

```text
PROBE_INPUT=POLICY_KEYS_DIAGNOSTIC_ONLY (checkpoint rename bypassed)
INFERENCE_01_MS=1208.24 ACTIONS=50
INFERENCE_02_MS=362.78 ACTIONS=50
INFERENCE_03_MS=385.49 ACTIONS=50
INFERENCE_04_MS=365.22 ACTIONS=50
INFERENCE_05_MS=359.99 ACTIONS=50
INFERENCE_06_MS=369.63 ACTIONS=50
INFERENCE_07_MS=371.92 ACTIONS=50
INFERENCE_08_MS=365.09 ACTIONS=50
INFERENCE_09_MS=360.29 ACTIONS=50
INFERENCE_10_MS=359.84 ACTIONS=50
INFERENCE_MEDIAN_MS=365.16
```

10회 중앙값은 `365.16 ms`다. HUB SmolVLA 기준 `480~520 ms`보다 114.84~154.84ms
짧지만, 첫 회 워밍업은 `1208.24 ms`였다.

실패 원인은 LeRobot 0.6.1의 처리 순서다. `prepare_raw_observation()`이 rename processor보다
먼저 아래 조회를 한다.

```python
policy_image_features[key].shape
```

여기서 `key`는 `observation.images.scene`인데 정책 feature에는
`observation.images.base_0_rgb`만 있어 `KeyError`가 난다. 서버는 그 뒤 만들
preprocessor의 saved rename map도 클라이언트가 보낸 값으로 override한다. 따라서
“콘솔은 scene/wrist를 유지하고 서버가 체크포인트 map으로 바꾼다”는 현재 계약은 이 버전의
async inference 구현과 맞지 않는다.
